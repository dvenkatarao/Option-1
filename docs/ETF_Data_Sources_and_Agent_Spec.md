# US ETF Research & Recommendation App - Data Sources and Agent Build Spec

> Generated by the running app. Source verification date: **2026-10-17**.
> Hand this entire file to an AI coding agent. It lists only sources that were tested from a live environment or read in official documentation, states which is which, and lists known data gaps so the agent does not invent data.

---

## 1. Non-negotiable data-integrity rules ("zero hallucination" contract)

1. **No number is ever produced by a language model.** Every displayed figure is either (a) copied verbatim from a provider response, or (b) computed by deterministic code from raw provider series using the formulas in section 5.
2. **Provenance on every datum:** store `source`, `source_url`, `as_of` (provider timestamp) and `fetched_at` (our timestamp). The UI must show the source and as-of date next to every metric group.
3. **Missing means missing.** If a provider does not return a field, store `NULL` and render "N/A". Never impute, never carry forward silently, never backfill from memory.
4. **Staleness is explicit.** Each dataset has a TTL. On upstream failure serve the last good copy with a visible STALE badge and its original timestamp; if nothing exists show "unavailable".
5. **Cross-check before trust.** Compare overlapping fields from two sources (e.g. expense ratio: Yahoo vs Alpha Vantage vs prospectus). On disagreement above tolerance, show both values and flag the ETF.
6. **LLM features (summaries, chat, recommendations text) may only paraphrase a structured JSON payload supplied by the backend,** must cite fields by name, and must refuse when the payload lacks the data. Temperature 0. Output is validated against the payload (every number in the text must exist in the payload).
7. **Recommendations are rule-based and transparent** (weights shown, percentile-ranked against the displayed universe) with a "not investment advice; past performance does not predict future results" disclaimer.
8. **Respect provider terms.** Unofficial endpoints (Yahoo, Cboe CDN, EDGAR FTS JSON) are prototype-grade: isolate each behind an adapter interface so a licensed provider can replace it.
9. **Set a real SEC User-Agent** (contact email) and stay under 10 requests/second to SEC hosts.
10. **Secrets** (API keys) live only in server-side environment variables; never ship to the browser.

### ETF universe boundary and discovery rules

- The runtime universe is the union of the curated seed list and active U.S.-listed stock instruments returned by Massive/Polygon with `market=stocks`, `locale=us`, `active=true`, and the explicit provider classification `type=ETF`. No additional liquidity cutoff is applied.
- ETNs and mutual funds are not ETF candidates: provider type `ETN` is classified separately from `ETF`, and only exact `ETF` types enter the universe. SEC ticker/CIK maps may support identity crosswalks, but are not used to determine whether an instrument is an ETF.
- Leveraged and inverse ETFs stay in the discovered universe and are tagged by the existing name/category risk rules; they are not silently presented as ordinary unleveraged funds. Downstream risk and recommendation behavior remains unchanged.
- Without `POLYGON_API_KEY`, the app uses its curated seed list (and a previously cached discovery snapshot, if present). It does not infer ETF status from ticker text.
- Successful full listings are stored in the existing Postgres-backed cache for 24 hours and served stale on provider errors. Background discovery retries after a 6-hour provider-failure backoff. Pagination is limited to 1,000 rows per request and eight pages, with at least 12.5 seconds between page requests; an incomplete listing is never published as a full snapshot.
- In production, discovery and hydration start automatically when `POLYGON_API_KEY` is set. The listing cache is refreshed daily; a separate background job hydrates at most 8 stale tickers every 15 minutes with 4 concurrent workers. `ETF_UNIVERSE_DISCOVERY=false` disables it; set it to `true` to enable the job outside production. Manual discovery only updates the ticker catalog and does not hydrate all symbols.
- Screener hydration remains on the existing Yahoo adapter. The UI batch is 8 tickers, the refresh API is capped at 16, and all batches retain bounded concurrency.

## 3. Analyst-opinion reality check

- No free API provides analyst ratings or price targets for the ETF itself. Morningstar ratings are paid; Yahoo's morningStarOverallRating field came back empty for SPY.
- What IS verifiable and free: stock-level analyst consensus (Yahoo financialData/recommendationTrend - tested; Finnhub /stock/recommendation - free key). This app aggregates it by holding weight for the top holdings and states the coverage % explicitly.
- For bond, commodity and crypto ETFs the holdings are not covered equities, so the app shows 'not available' instead of inventing a rating.

## 4. Known gaps (surface these in the UI, do not paper over them)

- True NAV history and premium/discount history: no free API. Yahoo gives a single navPrice snapshot (when present); issuers publish daily NAV files.
- Return-of-capital % per distribution (the real driver of NAV erosion): only in sponsor Section 19(a) notices and annual tax reclassification. The app therefore reports a market-price-based erosion PROXY and labels it as such.
- Real-time (non-delayed) quotes and consolidated volume: paid. Free options are delayed (Yahoo) or IEX-only (Alpaca).
- Economic consensus forecasts (what economists expect for CPI, NFP): proprietary. Free sources give release dates only (BLS ICS, FOMC calendar, BEA).
- ETF fund flows, creation/redemption data, bid-ask spread history, short interest by ETF: not covered by the free sources above.
- Full ETF holdings via API: Finnhub, FMP and Twelve Data gate them behind paid plans. Free path = Yahoo top-10, Alpha Vantage ETF_PROFILE (25/day), SEC N-PORT bulk (authoritative), sponsor files.

## 5. Metric definitions (implement exactly; unit-test with fixtures)

Inputs: daily series `close` (split-adjusted) and `adjclose` (split + distribution adjusted), distributions list `(ex_date, amount)`.

- **Price return** = close_end / close_start − 1
- **Total return** = adjclose_end / adjclose_start − 1 (distributions reinvested on ex-date)
- **Annualised** (windows > 1y only, only when history reaches back to the window start): (1 + r)^(365.25 / calendar_days) − 1
- **Volatility** = stdev(daily adjclose returns) × √252 (1y and 3y)
- **Max drawdown** = min_t( adjclose_t / running_peak − 1 ) over 3y/5y
- **Sharpe (3y)** = (annualised 3y total return − risk-free) / 3y volatility, risk-free = latest 3-month Treasury (FRED DGS3MO)
- **Beta / correlation vs benchmark** = cov(r_etf, r_bench) / var(r_bench), Pearson on date-aligned daily returns (3y)
- **TTM distribution yield** = sum(distributions with ex-date in last 365d) / last close
- **Distribution growth** = TTM / prior-TTM − 1; **3y CAGR** = (TTM / TTM_3y_ago)^(1/3) − 1
- **Frequency** = count of distributions in last 12 months (≥48 weekly, ≥10 monthly, ≥3 quarterly, 2 semi-annual, else annual/irregular)
- **NAV erosion proxy (market-price based)**
  - annualised price return over 1y/3y/5y (price return < 0 while distributions > 0 = share price decaying)
  - capital-funded share = min(1, −annualised price return ÷ annualised distribution yield) when price return < 0, else 0
  - level: None (≥ 0), Mild (> −2%/yr), Moderate (> −6%/yr), Severe (≤ −6%/yr). Thresholds are heuristics and must be labelled as such.
  - **Authoritative alternative:** return-of-capital % from sponsor Section 19(a) notices (not available via free API).
- **Premium/discount** = price / NAV − 1 only when a provider supplies NAV for the same date; otherwise N/A.
- **Holdings-weighted analyst consensus** = Σ w_i × recommendationMean_i / Σ w_i over holdings with coverage, where weights are fund weights; always display covered weight % and holdings counted / listed.

## 6. Suggested architecture

- **Stack:** Next.js (App Router) + PostgreSQL + Drizzle ORM. Server-side data adapters; no provider calls from the browser.
- **Adapters:** one module per provider implementing the same interface (`getHistory`, `getProfile`, `getQuote`, `getHoldings`) so providers can be swapped.
- **Tables:** `etfs` (profile + computed metrics + per-field source map), `etf_history` (compact daily series), `etf_distributions`, `etf_holdings_snapshots`, `macro_series`, `news_items`, `calendar_events`, `cache_entries`, `provider_health`.
- **Jobs:** refresh the Massive/Polygon ETF listing daily when `POLYGON_API_KEY` is configured; hydrate at most 8 stale ETFs per 15-minute background cycle with 4 concurrent workers. Quotes every 60 s (cached), macro hourly, news 10 min, FOMC/BLS calendars 6 h, N-PORT quarterly, EDGAR earnings 15 min.
- **Resilience:** stale-on-error cache, per-provider concurrency and rate limit tokens, exponential back-off on 429/5xx, health page that pings every source.
- **Pages:** dashboard, screener (filter/sort), ETF detail (performance, risk, distributions, NAV erosion, holdings, analyst consensus, news), compare (growth chart, side-by-side, correlation), recommendations (goal-based rule scoring), macro (yield curve + indicators), news & events (FOMC, releases, earnings, announcements), sources/health.

## 7. Build phases for the agent

1. Seed universe from SEC maps; resolve ETF flag + names live.
2. Price/distribution ingestion + metric engine with unit tests against hand-checked fixtures.
3. Profile ingestion (fees, AUM, holdings) with two-source cross-check.
4. Screener + detail + compare UI with provenance footers.
5. Macro, FOMC, release calendar, earnings & announcements feeds.
6. Rule-based recommendation engine (documented weights).
7. Optional LLM explainer constrained by rule 6 of section 1.
8. Provider health dashboard, alerting on schema drift (parser tests that fail loudly).
